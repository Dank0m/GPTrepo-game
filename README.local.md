# Frontier — локальная версия игры

Рабочая копия открытой части [OpenFront.io](https://openfront.io/) для собственного сервера и разработки. Основа — полный исходный пакет [openfrontio/OpenFrontIO](https://github.com/openfrontio/OpenFrontIO), коммит `817c12927c4ec34ec68c74c780a74a14fb776d09`. В этой версии изменено основное название; она не является официальным сервисом OpenFront и не связана с его операторами.

В пакете сохранены игровой движок, карты и ресурсы из репозитория, боты, строительство, дипломатия, одиночные партии и сервер сетевых матчей. Официальные учётные записи, статистика аккаунтов, покупки и закрытые API/CDN-ресурсы не входят в открытый исходный код и здесь не воспроизводятся. Для локальной анонимной игры они не нужны.

## Установка

Требуются Node.js версии **24.15 или новее в ветке 24**, npm **12.1 или новее в ветке 12** и браузер с WebGL2.

В подготовленной облачной среде npm 12 уже установлен отдельно от проекта. Перед командами установки, запуска и проверки добавьте его в путь:

```bash
export PATH=/workspace/.tools/npm/node_modules/.bin:$PATH
export npm_config_cache=/workspace/.cache/npm
```

Если установлен более старый npm:

```bash
npm install --global --ignore-scripts npm@12.1.0
```

В каталоге проекта:

```bash
node --version
npm --version
npm run inst
```

`npm run inst` запускает `npm ci --ignore-scripts`: устанавливает версии из `package-lock.json` без выполнения установочных скриптов. Сохраняйте ограничения доверия и возраста пакетов в `.npmrc`.

## Запуск

```bash
cd /workspace/GPTrepo-game
SKIP_BROWSER_OPEN=true npm run dev:host
```

Команда запускает клиент на порту **9000**, координатор игр на **3000** и два игровых процесса на **3001–3002**. Терминал должен оставаться открытым; `Ctrl+C` останавливает запуск. После перезапуска облачной машины команду нужно выполнить снова.

`dev:host` открывает доступ к клиенту через сетевой интерфейс машины. Если нужен только доступ с самой машины, используйте `SKIP_BROWSER_OPEN=true npm run dev`.

В режиме разработки не задавайте `API_DOMAIN`, `CDN_BASE`, `SUBDOMAIN` и `LOBBY_COORDINATOR` для официальных серверов. Скрипт сервера сам задаёт `GAME_ENV=dev` и `DOMAIN=localhost`; пользовательские API-ключи для локального режима не требуются. `example.env` описывает также развёртывание оригинального проекта — копировать его целиком для локальной игры не нужно.

Проверка готовности из другого терминала:

```bash
curl --fail http://127.0.0.1:9000/api/health
```

Ожидается HTTP 200 и JSON с `"status":"ok"`. Пока игровые процессы запускаются, возможен HTTP 503.

## Как играть

- Выберите язык в меню, при необходимости русский.
- Для одиночной партии откройте одиночный режим, выберите карту, сложность и число ботов, запустите матч и выберите стартовую точку на суше.
- Для игры с друзьями создайте приватное лобби и передайте его ссылку участникам. Их браузеры должны иметь доступ к запущенному серверу; адрес с `localhost` на другой машине не подойдёт.

Одиночная симуляция работает в браузере. Сетевой режим использует собственный локальный сервер, а не игроков и матчи официального OpenFront.io. Без отдельного закрытого API запросы учётных записей и магазина могут завершаться ошибками; это не подключение к официальному аккаунту.

В этой версии отключены внешние рекламные и аналитические интеграции. Недоступность необязательного API аккаунтов и косметики не блокирует создание и запуск локальных приватных лобби.

## Проверки и сборка

```bash
npm run typecheck
npm test
npm run build-prod
```

Это команды проверки и сборки, а не утверждение, что все тесты прошли в любой среде. Результаты текущего запуска приведены в отчёте о выполнении задачи. `build-prod` создаёт `static/`; самостоятельное публичное размещение дополнительно требует настройки маршрутизации HTTP/WebSocket и раздачи ресурсов. `dev:host` предназначен для разработки.

Закрытый необязательный подмодуль `src/server/gatekeeper` для разработки не нужен. При его отсутствии исходный сервер штатно использует реализацию без дополнительных проверок этого модуля.
